# Entrar con Google en Brújula, sin servidor de correo

Esta opción usa Google para demostrar la identidad del usuario y **Supabase Auth** para crear la sesión. Vercel solo sirve la página. El código cliente ya muestra «Continuar con Google»; hasta activar el proveedor, el botón no puede completar el acceso. No se cambia ninguna política RLS ni se guarda un secreto OAuth en el repositorio.

## Activación para el proyecto Brújula

1. En [Google Auth Platform](https://console.cloud.google.com/auth/overview), crea o selecciona un proyecto propio. En **Branding** configura Brújula; en **Audience** elige **External** si quieres permitir cuentas Google de otros usuarios. Mientras esté en modo de prueba, incluye tus cuentas de prueba según te indique Google. En **Data Access** usa únicamente `openid`, `userinfo.email` y `userinfo.profile`; no pidas acceso a Drive, Gmail ni información financiera.
2. En **Clients → Create client → Web application**, añade como **Authorized JavaScript origin** `https://brujula-finanzas-gamma.vercel.app` y, si pruebas localmente, `http://localhost:5173`. Como **Authorized redirect URI**, añade **exactamente** `https://nvbkftnithuduyazhidc.supabase.co/auth/v1/callback`. Google enviará la respuesta a Supabase, no directamente a Vercel. Copia el Client ID y el Client Secret.
3. En [Supabase → Authentication → Sign In / Providers → Google](https://supabase.com/dashboard/project/nvbkftnithuduyazhidc/auth/providers), activa Google y pega allí el **Client ID y Client Secret**. El secreto se guarda solo en Supabase, nunca en GitHub ni en una variable `VITE_`.
4. En [Supabase → Authentication → URL Configuration](https://supabase.com/dashboard/project/nvbkftnithuduyazhidc/auth/url-configuration), establece Site URL como `https://brujula-finanzas-gamma.vercel.app` y permite **solo** las URLs de retorno previstas: `https://brujula-finanzas-gamma.vercel.app` y `http://localhost:5173` si la usas. Evita comodines de redirección en producción. La aplicación envía `redirectTo: window.location.origin`.
5. Despliega la versión con el botón **después** de terminar los pasos anteriores. Comprueba el acceso con una cuenta Google de prueba, cierra sesión, entra de nuevo y verifica que los movimientos son los mismos desde otro dispositivo. Comprueba también que otro usuario no puede leerlos. Si ya existía una cuenta por correo, prueba el mismo email y comprueba que se conserva el `user.id` y sus movimientos **antes de migrar usuarios reales**. Supabase puede enlazar automáticamente identidades con el mismo email verificado, pero no hay que asumir la vinculación sin probarla.

El acceso por código permanece como opción secundaria, etiquetada «si está activado». Sin SMTP propio sigue sujeto a los límites del proveedor de correo integrado; Google no consume ese cupo. No desactives RLS ni la confirmación de correo de otros flujos para intentar que Google funcione. El alojamiento de Vercel no necesita claves nuevas.

Documentación oficial: [Google OAuth](https://supabase.com/docs/guides/auth/social-login/auth-google), [URLs de retorno](https://supabase.com/docs/guides/auth/redirect-urls), [vinculación de identidades](https://supabase.com/docs/guides/auth/auth-identity-linking), [precio de Supabase](https://supabase.com/pricing).
